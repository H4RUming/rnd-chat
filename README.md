# R&D 검색 채팅

여러 MCP 서버를 묶어, 모델이 필요할 때 자료를 직접 찾아 답하는 채팅입니다. 지원사업 공고(기업마당)와 국가R&D 과제(NTIS)를 찾고 취합하는 데 씁니다.

MCP 서버들은 각자 다른 저장소에 있고 따로 띄웁니다. 이 저장소는 그 서버들에 붙는 쪽만 다룹니다.

| 서버 | 기본 주소 | 하는 일 |
|---|---|---|
| bizinfo | `http://127.0.0.1:8765/mcp` | 진행 중인 지원사업 공고와 첨부 본문 검색 |
| linkreader | `http://127.0.0.1:8766/mcp` | 공고에 걸린 외부 링크 읽기 |
| history | `http://127.0.0.1:8767/mcp` | 마감 포함 공고 이력 검색과 집계 |
| ntis | `http://127.0.0.1:8768/mcp` | 국가R&D 과제·성과·연구보고서 검색과 집계 |

## 지금 되는 것

- 설정 파일로 모델 서버, MCP 서버 목록, 로그인 계정을 정합니다.
- 모델이 도구를 부르면 해당 서버에서 실행해 결과를 돌려주고, 글로 답할 때까지 되풀이합니다(에이전트 루프).
- 로그인해야 쓸 수 있는 웹 채팅 화면이 있습니다.
  - 답이 글자 단위로 흘러나오고, 모델이 어떤 도구를 어떤 조건으로 불렀고 무엇이 나왔는지 단계별로 펼쳐 볼 수 있습니다. 도중에 멈출 수 있습니다.
  - 답에서 자료에 근거한 부분은 형광펜으로 칠해집니다. 마우스를 올리면 그 공고·과제의 요약 카드가 뜨고, 누르면 원문이 새 탭에서 열립니다(아래 "출처 표시").
  - 답의 표·목록·코드·링크를 그리고, 답 복사와 다시 생성을 할 수 있습니다.
  - 대화 목록은 날짜별로 묶이며 찾기, 제목 바꾸기, 지우기가 됩니다.
  - 밝은·어두운 화면, 사이드바 접기, 휴대폰 화면을 지원합니다.
- 문서를 첨부하면 그 원본을 고쳐서 돌려줍니다(아래 "문서 작업").
  - 한글(HWP·HWPX)·워드(DOCX) 양식을 올리고 "우리 회사 정보로 채워줘"라고 하면, 양식의 모양은 그대로 두고 칸만 채운 같은 형식의 파일을 줍니다.
  - 고친 파일은 화면에서 쪽 단위로 미리 보고, 무엇이 바뀌었는지 목록으로 확인하고, 원본과 번갈아 볼 수 있습니다.
  - "엑셀로 정리해줘", "보고서로 만들어줘", "한글 파일로 줘"라고 하면 엑셀(XLSX)·워드(DOCX)·한글(HWPX) 파일을 새로 만들어 줍니다.
  - PDF 양식은 원본을 고칠 수 없으므로, 그 모양을 따라 새 문서를 만들어 채웁니다.
  - 이미 받은 답도 버튼 하나로 워드 문서나 엑셀(답 안의 표)로 저장할 수 있습니다.
- 터미널에서도 질문해 볼 수 있습니다.

아직 없는 것: 외부 공개용 터널 설정, 대화 저장(서버를 다시 띄우면 대화가 사라집니다).

## 설치

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
cp config.example.toml config.toml && chmod 600 config.toml   # config.toml 은 git 에 올라가지 않는다
# config.toml 의 [llm] base_url 을 모델 서버 주소로 고친다
.venv/bin/python -m chat.cli --tools                           # 붙은 MCP 서버와 도구 확인
```

모델 서버는 OpenAI 호환 API(`/v1/chat/completions`)와 도구 호출(`tool_calls`)을 지원해야 합니다. 모델 서버에는 추론 요청만 보냅니다.

## 웹 채팅

계정을 먼저 만듭니다. 비밀번호 해시를 만들어 `config.toml`에 붙여 넣습니다.

```bash
.venv/bin/python -m chat.passwd        # 비밀번호를 두 번 묻고 password_hash = "…" 한 줄을 내놓는다
```

```toml
[[users]]
name = "이름"
password_hash = "scrypt$…"
```

```bash
.venv/bin/python -m chat.web           # http://127.0.0.1:8080
```

계정이 하나도 없으면 서버는 뜨지 않습니다. `password = "평문"`으로 적어도 동작하지만, 시작할 때 경고가 나오며 해시를 권합니다.

### 접근 통제와 보안

외부에 공개할 것을 전제로 만들었습니다.

- **기본은 127.0.0.1에만 엽니다.** 밖에서는 터널을 거쳐서만 들어옵니다. 내부망의 다른 기기에서 접속하려면 아래 "내부망에 https로 열기"를 따릅니다.
- **로그인 화면과 정적 파일 말고는 모두 세션이 필요합니다.** 쿠키에는 무작위 토큰만 싣습니다(`HttpOnly`, `SameSite=Strict`, https면 `Secure`). 세션은 서버 메모리에 두고, `data_dir` 이 있으면 대화 파일에도 적어 서버를 다시 띄워도 로그인이 유지됩니다(파일에는 토큰이 아니라 토큰의 해시를 적고, 비밀번호를 바꾸거나 계정을 지우면 그 계정의 남은 세션은 버립니다). 쓰지 않으면 `session_hours` 뒤에 끊기고, 길어도 7일이며, 한 계정의 세션은 5개까지입니다.
- **로그인 시도 제한.** 한 계정에서 5번 연달아 틀리면 60초 잠기고, 풀린 뒤 또 틀리면 두 배씩 늘어납니다(최대 1시간). 접속 IP별로도 더 느슨한 한도(20번)를 둡니다. 계정이 없는지 비밀번호가 틀렸는지는 구분해 알려 주지 않고, 걸리는 시간도 같게 맞춥니다.
- **비밀번호는 scrypt 해시로 대조합니다.**
- **요청 위조 방지.** 상태를 바꾸는 요청은 `Origin`이 같은 호스트여야 하고, API는 전용 헤더까지 있어야 합니다.
- **허용한 호스트 이름으로 온 요청만 받습니다**(`allowed_hosts`). 외부 공개 시 공개 도메인을 더합니다.
- **보안 헤더.** 모든 응답에 CSP(인라인 스크립트 금지, 외부 자원 금지), `X-Frame-Options: DENY`, `nosniff`, `Cache-Control: no-store, no-transform`을 붙입니다(`no-transform`은 Cloudflare 같은 앞단이 화면에 분석 스크립트를 끼워 넣지 못하게 합니다). https로 들어온 요청에는 HSTS도 붙습니다. 화면은 외부 글꼴·스크립트 없이 이 서버의 파일만 씁니다.
- **모델의 답은 신뢰하지 않습니다.** 브라우저에서 `innerHTML` 없이 DOM 노드로만 그리고, 링크는 http·https만 허용합니다.
- **대화는 계정별로 따로 둡니다.** 남의 대화는 id를 알아도 볼 수 없습니다.
- **동시에 처리하는 질문 수를 묶습니다**(`max_concurrent`). 한 사람이 답을 기다리는 동안 또 보낼 수 없습니다.
- 내부 오류 내용은 화면에 내보내지 않고 서버 로그에만 남깁니다. 로그인 성공·실패는 이름과 IP로 기록합니다.

### 내부망에 https로 열기

같은 망(LAN, Tailscale 등)의 다른 기기에서 접속하려면 `0.0.0.0`에 열고 https를 켭니다. 로그인 비밀번호와 대화가 망 위를 그대로 지나가지 않게 하기 위해서입니다.

```bash
.venv/bin/python -m chat.tlscert --name 호스트이름 --ip 192.168.0.10     # 접속에 쓸 이름·주소를 모두 적는다
```

```toml
[web]
host = "0.0.0.0"
port = 8443
tls_cert = "certs/cert.pem"
tls_key = "certs/key.pem"
allowed_hosts = ["127.0.0.1", "localhost", "호스트이름", "192.168.0.10"]
```

`python -m chat.tlscert`는 자체 서명 인증서를 만듭니다(`openssl` 필요, `certs/`는 git에 올라가지 않습니다). 자체 서명이라 브라우저가 처음 접속할 때 경고를 보여 줍니다. 경고를 없애려면 접속하는 기기에 `certs/cert.pem`을 신뢰하는 인증서로 등록하거나, 공인 인증서를 받아 같은 설정에 넣습니다(Tailscale이면 `tailscale cert`). https를 켜지 않고 `0.0.0.0`에 열면 시작할 때 경고가 나옵니다.

HSTS는 직접 https로 열었을 때는 붙이지 않습니다. 내부망 이름에 붙이면 브라우저가 그 이름의 다른 포트(http 서비스)까지 https로 바꿔 버리기 때문입니다.

### Cloudflare 터널 뒤에 둘 때

브라우저와 Cloudflare 사이의 https는 Cloudflare가 맡습니다. 터널(`cloudflared`)과 이 서버는 같은 장비에서 오가므로 두 가지 모두 됩니다.

- 이 서버를 http로 두고(`tls_cert` 없음, `host = "127.0.0.1"`) 터널이 `http://localhost:8080`으로 붙는 방식. 가장 단순합니다.
- 이 서버를 https로 둔 채 터널이 `https://localhost:8443`으로 붙는 방식. 자체 서명 인증서면 터널 설정에 `originRequest: noTLSVerify: true`를 주거나 `caPool`로 `certs/cert.pem`을 지정합니다.

어느 쪽이든 `[web]`의 `allowed_hosts`에 공개 도메인을 더하고 `trust_forwarded = true`로 바꿉니다. 그래야 접속 IP별 제한이 실제 접속자 기준으로 걸립니다. 터널 없이 이 값을 켜면 접속자가 IP를 속일 수 있으니 켜지 않습니다. 터널을 거쳐 들어온 요청에는 HSTS가 붙습니다.

## 출처 표시

자료 서버가 돌려준 공고·과제·보고서에는 서버가 번호를 매겨 모델에 보여 줍니다. 모델은 그 자료에 근거해 쓴 문장 뒤에 `[번호]`를 붙이고, 화면은 그 문장을 형광펜으로 칠합니다.

- 형광펜 부분이나 번호에 마우스를 올리면 자료 카드(이름, 기관·기간·금액 같은 주요 항목, 요약, 주소)가 뜹니다. 누르면 원문이 새 탭에서 열립니다. 터치 화면에서는 한 번 누르면 카드가, 카드의 링크를 누르면 원문이 열립니다.
- 답 아래에는 그 답이 가리킨 출처가 모여 나옵니다. 답을 복사하거나 워드로 저장하면 출처 목록이 함께 들어갑니다.
- 번호와 주소는 도구 결과에 있던 것만 씁니다. 모델이 지어낸 번호는 형광펜이 되지 않고 글자 그대로 남습니다.
- 화면에 보이는 번호는 답마다 처음 나온 순서대로 1, 2, 3 … 입니다(안에서는 대화 전체에서 이어지는 번호를 씁니다).
- 집계 수치처럼 가리킬 원문이 하나가 아닌 결과에는 번호가 붙지 않습니다.

## 문서 작업

모델에는 MCP 서버의 도구 말고도 이 서버 안의 도구 넷이 보입니다.

| 도구 | 하는 일 |
|---|---|
| `edit_document` | 첨부한 HWP·HWPX·DOCX 의 원본을 그대로 두고 내용만 고쳐 같은 형식으로 돌려줍니다: 표의 칸 채우기, 글 바꾸기, 문단 바꾸기·추가, 표에 행 추가, 누름틀 채우기 |
| `inspect_document` | 문서의 표 하나를 전부 보거나, 특정 쪽을 그림으로 다시 봅니다 |
| `create_document` | 워드(DOCX)나 한글(HWPX) 문서를 새로 만듭니다. 표의 칸 합치기를 지원합니다 |
| `create_spreadsheet` | 엑셀(XLSX)을 만듭니다. 숫자는 숫자로, 주소는 링크로 들어갑니다 |

**첨부한 문서를 고치는 흐름.** 입력창의 클립 버튼이나 화면에 끌어다 놓기로 문서를 올립니다. 서버는 원본을 그대로 보관하고, 모델에는 쪽 그림(앞 8쪽)과 "개요"를 보냅니다. 개요에는 문단 번호와 표의 칸 좌표가 적혀 있어, 모델이 `표 0 의 1행 2열` 처럼 고칠 곳을 가리킵니다. 고친 뒤에는 바뀐 쪽의 그림이 모델에 되돌아가므로 모델이 결과를 직접 확인하고 다시 고칠 수 있습니다. 문서를 새로 그리지 않기 때문에 글꼴·표·여백이 원본 그대로 남습니다.

**한글 문서 엔진.** HWP·HWPX 는 [rhwp](https://github.com/edwardkim/rhwp)(MIT) 실행 파일을 불러 고치고, 미리보기 쪽도 같은 엔진으로 그립니다. 설정의 `[documents] rhwp` 에 경로를 적거나 PATH 에 둡니다. 엔진이 없으면 한글 문서는 읽기만 되고(쪽 그림은 LibreOffice 로 그립니다), 워드 문서는 엔진 없이 고칩니다. 공식 배포 파일이 없는 장비(ARM 등)에서는 소스에서 빌드합니다. 메모리가 8GB 인 장비에서는 기본 릴리스 설정(전체 최적화)으로는 빌드가 메모리 부족으로 끝나므로 이렇게 낮춰 빌드했습니다.

```bash
cargo build --release --locked --bin rhwp -j 2 \
  --config 'profile.release.lto="off"' --config 'profile.release.codegen-units=16' \
  --config 'profile.release.package.rhwp.opt-level=1' --config 'profile.release.package.rhwp.codegen-units=256'
```

**미리보기.** 파일 카드의 "미리보기"(고친 파일은 "확인하기")를 누르면 쪽 그림이 열립니다. 고친 파일은 바뀐 내용 목록이 옆에 나오고, 항목을 누르면 그 쪽으로 갑니다. "원본 보기"로 고치기 전과 번갈아 볼 수 있습니다.

**받은 답을 저장하는 경우.** 답 아래의 버튼으로 그 답을 워드 문서로, 답 안의 표를 엑셀로 내려받습니다. 모델을 다시 부르지 않고 서버가 바로 바꿉니다.

알아둘 점:

- 채우는 값은 사용자가 알려 준 정보와 도구로 찾은 자료뿐입니다. 모르는 칸은 그대로 둡니다. 내려받은 파일은 제출 전에 한글·워드에서 한 번 열어 확인하세요.
- 미리보기의 쪽 나눔과 글꼴은 실제 한글·워드 프로그램과 조금 다를 수 있습니다(서버에 없는 글꼴은 다른 글꼴로 그립니다). 파일 자체에는 원본의 글꼴 지정이 그대로 있습니다.
- 한글 문서에서 칸 좌표로 고칠 수 있는 것은 본문에 바로 놓인 표입니다. 다른 표의 칸 안에 든 표, 글상자 안의 글은 "글 바꾸기"로만 고칩니다.
- PDF 는 원본을 고칠 수 없어 모양을 따라 새로 만듭니다. 표가 복잡하면 칸 합치기가 원본과 달라질 수 있습니다.
- 생각하는 모델(Qwen 등)은 `[llm] thinking = true` 로 답하기 전에 속으로 따져 보게 할 수 있습니다. 검색어를 넓히고 다시 찾을지 판단하는 데 도움이 되지만, 검색 결과 수만 자를 받은 뒤에도 켜 두면 답 하나에 몇 분이 걸릴 수 있어(실측 5분) 질문마다 앞의 `[agent] thinking_steps` 단계(기본 1: 무엇을 어떻게 찾을지 정하는 단계)에서만 씁니다. 그 단계의 길이는 `thinking_tokens`(기본 4000)로 묶고, 넘거나 속생각만 하고 빈 답으로 끝나면 생각을 끄고 한 번 더 묻습니다. `thinking_steps = 0` 이면 모든 단계에서 제한 없이 생각합니다.
- 올리는 파일은 HWP·HWPX·DOCX·PDF, 15MB 까지, 한 질문에 3개까지 받습니다. 확장자가 아니라 내용으로 종류를 가리고, 암호가 걸렸거나 손상된 파일은 거절합니다.
- 문서를 다루는 프로그램(rhwp, LibreOffice, poppler)은 별도 프로세스로, 빈 환경과 임시 폴더에서, 제한 시간을 두고 돌립니다. LibreOffice 는 매크로와 바깥 자료 불러오기를 끈 임시 프로필로 돕니다. 쪽 그림과 워드·엑셀 미리보기에 `poppler-utils` 와 LibreOffice 가 필요합니다.
- 파일은 `data/files/` 아래 계정별 폴더에 무작위 이름으로 둡니다. 사용자가 준 파일 이름은 표시에만 씁니다. 남의 파일은 id 를 알아도 받거나 볼 수 없고, 모든 파일은 내려받기로만 나갑니다(브라우저가 열어 실행하지 않게).
- 엑셀에서 `=`로 시작하는 글은 수식으로 실행되지 않게 글로 넣습니다.
- 대화가 메모리에만 있으므로 서버를 다시 띄우면 보관한 파일도 지웁니다. 계정당 200개·300MB 를 넘으면 오래된 것부터 지웁니다.

## 동작 방식과 상한

- MCP 서버에는 호출마다 연결을 새로 맺습니다. 서버 하나가 죽어 있으면 그 서버만 빼고 답하며, 모델에게 그 사실을 알립니다.
- 도구 이름이 서버끼리 겹치면 `서버이름__도구이름`으로 구분합니다.
- **비서**(`chat/tasks.py`, 설정 `[briefing]`): 왼쪽 메뉴의 **비서**는 계정마다 하나 있는 대화입니다. 거기서 "강원도 드론 공고 새로 뜨면 알려줘", "매주 월요일에 양자 과제 정리해줘"처럼 말로 일을 맡기면 모델이 `save_task` 로 저장하고(요일·시각, 알릴 조건, 메일 여부), 정해진 때에 평소와 같은 검색 도구로 그 일을 해서 **같은 대화에** 결과를 올립니다. 결과를 보고 "마감된 건 빼줘"라고 하면 그 일의 내용을 고쳐 저장합니다. 일은 자동으로 생기지 않습니다(예전의 아침 브리핑은 대화에서 주제를 뽑아 자동으로 만들었는데, 그 주제들은 처음 띄울 때 "아침 브리핑"이라는 일 하나로 옮겨집니다). "새 것이 있을 때만" 알리는 일은 모델이 새 소식이 없다고 답했거나, 답이 가리킨 자료가 모두 지난번에 보여 준 것이면 올리지 않습니다. **맡긴 일** 탭에서 일마다 켜고 끄기, 지금 하기, 메일 켜고 끄기, 지우기를 할 수 있습니다. 서버가 꺼져 있던 시각의 일은 그날 안에 켜지면 그때 하고, 지난 날의 것은 건너뜁니다. 그래서 그날 할 시각이 이미 지난 뒤에 맡긴 일은 곧바로 한 번 하고(첫 결과를 보고 고칠 수 있게), 다음부터 정한 시각에 합니다. `refresh_time` 을 주면 그보다 이르게 잡은 일도 자료 갱신 뒤에 합니다. 비서 대화의 출처는 답이 가리키는 것만 남기며 번호를 이어 씁니다. 메일은 `chat/mailer.py` 가 보내며, 본문에 들어가는 자료의 글은 모두 이스케이프하고 링크는 출처의 http(s) 주소로만 만듭니다. 비서 화면은 네 탭입니다 — **오늘**(그날 올라온 결과를 맨 위 두세 줄로 간추린 카드, 하는 중·실패·예정, 권하는 일), **대화**, **맡긴 일**, **메모**. 카드의 좋아요·별로예요는 그 일에 적혀 다음에 할 때 반영됩니다. **메모**는 비서가 사용자의 사정·취향을 적어 두는 짧은 글(`save_note`)로, 일을 할 때와 비서와 이야기할 때마다 읽히고, 사용자가 보고 고치고 지우고 직접 적을 수 있습니다(30개까지). **권하는 일**은 보통 대화에서 거듭 물은 주제 가운데 아직 맡기지 않은 것을 하루 한 번(기본 시각 이후, 지난번 뒤로 새 대화가 있었던 계정만) 모델에 물어 세 개까지 보여 주는 것으로(`chat/brief.py`), 받아들여야 일이 되고 물리면 다시 권하지 않습니다.
- **회원가입 신청**(설정 `[signup]`): 켜면 로그인 화면 아래에 "회원가입"이 생기고, 아이디·이메일·비밀번호를 받습니다. 바로 가입되지 않고 신청으로 남으며(비밀번호는 해시로만 저장), 관리자(`admin` 계정)에게 알림 메일이 갑니다. 관리자는 화면 왼쪽 **계정** 메뉴에서 승인하거나 거절하고, 승인하면 그 계정으로 로그인할 수 있게 되며 신청한 사람에게 승인 메일이 갑니다. 승인된 계정은 설정 파일이 아니라 `data/chat.sqlite3` 에 있고, 계정 메뉴에서 지우면 그 계정의 대화·문서·로그인도 함께 지워집니다. 신청은 같은 출처의 요청만 받고, 한 시간에 받는 수(`per_hour`, 접속 주소별로는 그 절반)와 쌓아 두는 수(`max_pending`)에 한도가 있습니다. 가입한 계정도 비서에게 일을 맡길 수 있고, 메일로 받겠다고 한 일의 결과는 가입할 때 적은 주소로 갑니다.
- **왼쪽 메뉴**: 새 대화 · 검색 · 비서 · 문서 · 도구. **검색**(`/api/search`)은 제목뿐 아니라 주고받은 글에서도 낱말을 찾아 그 둘레의 글을 보여 줍니다(Ctrl K). **도구**(`/api/status`)는 모델, 자료 서버마다 붙어 있는지와 쓸 수 있는 도구, 아침 자료 갱신의 결과(`[briefing] refresh_status` 의 파일)를 보여 주며, 열 때마다 자료 서버에 다시 붙어 봅니다. **문서**(`GET /api/files`)는 올린 문서와 모델이 만들거나 고친 문서를 대화와 상관없이 최근 것부터 모아 보여 주고(이름 검색, 올린 것·만든 것 가르기), 미리보기·내려받기·그 대화로 가기·지우기(`DELETE /api/files/{id}`)를 할 수 있습니다. 지운 문서는 대화의 카드에서도 빠지고, 답을 다시 생성하면 앞선 답이 만든 파일은 함께 지워집니다. 대화를 지워도 그 대화의 문서는 여기에 남습니다(계정당 200개·300MB 를 넘으면 오래된 것부터 지워집니다). 이 화면들은 대화 자리에 겹쳐 보이고 Esc 로 보던 대화에 돌아갑니다(답을 받는 중이어도 끊기지 않습니다).
- 대화는 `data/chat.sqlite3`(서버 계정만 읽을 수 있는 파일)에 남아 서버를 다시 띄워도 그대로 있습니다. 대화에 딸린 출처·작업 기록과, 올리거나 만든 파일(`data/files/`)도 함께 남습니다. 로그인 세션은 메모리에만 있어 다시 띄우면 다시 로그인해야 합니다. 설정에 자료 폴더가 없으면(시험용) 메모리에만 둡니다.
- 검색 결과를 일부만 보고 답하지 않도록 `review_all` 도구를 둡니다(`chat/sweep.py`). 검색 도구는 한 번에 100건까지만 주므로, 모델이 이 도구를 부르면 서버가 같은 조건으로 끝까지 넘겨 받아 자료마다 한 줄로 줄인 목록을 묶음 단위로 모델에 따로 보이고(조건에 맞는 번호만 고르게 합니다) 맞는 자료만 대화로 돌려줍니다. 결과에는 전체·확인한 수·맞은 수가 함께 나오고, 연도별로 따로 등록된 같은 과제는 하나로 합칩니다. 한 번에 넘겨 보는 양은 `[agent] sweep_max_items`(기본 5000건)·`sweep_seconds`(기본 600초)까지이며, 거기에 걸리면 끝까지 보지 못했다고 결과에 밝힙니다. 실측: NTIS 1,459건 확인에 약 1분.
- 질문 하나에 도구 왕복은 `max_steps`회(기본 24)까지입니다. 넘으면 도구 없이 지금까지 찾은 것으로 마무리하게 합니다. 도구 결과는 하나에 `tool_result_chars`자, 질문 하나에 합쳐 `turn_result_chars`자까지 모델에 넘깁니다(모델이 한 번에 읽을 수 있는 양을 넘으면 요청 자체가 실패하므로 합계에도 상한을 둡니다).
- 이어지는 질문에는 앞선 차례에 무엇을 어떤 조건으로 찾았고 전체 몇 건 중 몇 건을 봤는지를 모델에 알려 줍니다. 모델에는 앞선 질문과 답의 글만 넘어가므로, 이것이 없으면 앞선 답의 목록에서만 골라 답하게 됩니다.
- 도구 결과는 `tool_result_chars`자에서 자르고, 잘랐다는 사실과 전체 길이를 모델에 알립니다.
- 도구가 돌려준 그림(스캔 PDF, 화면 사진)은 `max_images`장까지 모델에 보입니다.
- 도구가 돌려준 내용은 자료로만 다룹니다. 그 안에 지시처럼 보이는 글이 있어도 따르지 않도록 안내문에 적어 둡니다.

|---|---|

| `chat/auth.py` | 계정, 비밀번호 대조, 로그인 시도 제한, 세션 |
| `chat/web.py` | 웹 서버: 접근 통제, 보안 헤더, 채팅 API |
